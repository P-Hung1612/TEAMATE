# HƯỚNG DẪN DÀNH CHO REPO OWNER / PRODUCT OWNER

Tài liệu này định nghĩa các bước thao tác chuẩn mực dành riêng cho bạn (người nắm giữ nhánh `main` và `dev`) để quản lý dự án hiệu quả và ngăn chặn rủi ro (Conflict/Chaos).

---

## 1. QUẢN LÝ NHÁNH VÀ MÔI TRƯỜNG

- **`main` (Production):** Nhánh thiêng liêng nhất. Code trên này luôn phải deploy được. Tuyệt đối không cho Collaborator push thẳng vào đây.
- **`dev` (Integration):** Nhánh hội tụ code. Mọi tính năng từ Collaborator phải thông qua Pull Request (PR) để gộp vào đây.
- **Tính Nhất Quán:** Không để `main` và `dev` khác nhau quá xa về mặt cấu trúc thư mục (ví dụ `dev` là monorepo nhưng `main` lại không phải).

---

## 2. QUY TRÌNH GIAO TASK (ASSIGN TASK)

- **Chia nhỏ Task:** Giao task càng rõ ràng, chi tiết thì PR càng nhỏ và ít bị conflict.
  - GOOD: "Làm Login UI", "Viết Auth API".
  - BAD: "Làm phần Frontend đi".
- **Quy định tên nhánh:** Ép buộc dev tuân thủ quy tắc `feature/<tên>` hoặc `fix/<tên>`.

---

## 3. QUY TRÌNH DUYỆT PULL REQUEST (PR)

Khi Collaborator tạo PR từ nhánh `feature/*` vào `dev`:

1. **Kiểm tra Scope (Phạm vi):** PR này có làm đúng 1 mục tiêu duy nhất không? 
   - KHÔNG merge PR khổng lồ (VD: 1 PR chứa cả login, navbar, darkmode). Nếu thấy to quá, hãy từ chối và yêu cầu tách nhỏ.
2. **Kiểm tra rác (Hygiene):** Đảm bảo không có `console.log` thừa, file không liên quan bị sửa nhầm.
3. **Chạy thử (Integration Test):** Đừng chỉ "thấy code chạy là merge". Kéo nhánh về, test xem khi ghép với các tính năng khác nó có làm sập app không.
4. **Approve & Merge:** Nếu ổn, bấm gộp vào `dev`.
5. **Dọn dẹp:** NHỚ XÓA nhánh `feature` đó ngay sau khi merge để giữ repo sạch sẽ.

---

## 4. PHÁT HÀNH (RELEASE) TỪ DEV LÊN MAIN

Khi các tính năng trên `dev` đã gom đủ và hoạt động cực kỳ ổn định (ví dụ: hoàn tất cụm tính năng MVP):

1. `git checkout main`
2. `git merge dev`
3. `git push origin main`
4. (Khuyên dùng) Đánh Tag phiên bản: `git tag -a v1.0.0-MVP -m "Release MVP"`

---

## 5. XỬ LÝ LỖI KHẨN CẤP (HOTFIX) TRÊN PRODUCTION

Nếu `main` đang chạy nhưng người dùng báo app bị crash:

1. Đứng từ `main` tạo nhánh sửa lỗi: `git checkout main` ➔ `git checkout -b fix/critical-bug`
2. Sửa lỗi, test cẩn thận.
3. Gộp bản vá này vào **CẢ HAI NHÁNH** (`main` và `dev`) để đồng bộ code, ngăn lỗi bị lặp lại trong tương lai:
   - `git checkout main` ➔ `git merge fix/critical-bug`
   - `git checkout dev` ➔ `git merge fix/critical-bug`

---

## TÓM LẠI: TƯ DUY CỐT LÕI
Một Repo chỉ có thể sống khỏe và scale lớn nếu thỏa mãn:
**Workflow đơn giản + Branch rõ ràng + PR nhỏ + Review cực kỳ khắt khe.**
